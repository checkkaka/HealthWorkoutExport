# Keep running to Strava

## Outcome and approved scope
Add Keep as an experimental account-based source in the Flutter/Rust migration application. Read the signed-in user's outdoor and indoor running records and upload selected records through the existing official Strava FIT upload workflow. Keep is not a supported public third-party API; the user accepted this limitation. This change does not modify the legacy Swift application or perform any real account login or upload during development.

## Source architecture
- Rust owns fixed-domain Keep HTTPS login, paginated running list, detail retrieval, bounded decoding, and conversion to standard running FIT.
- The Keep token and account identifier use the platform's existing secure store. Passwords are used once for login and are not persisted. Expired/challenged sessions require user re-login; no password replay or CAPTCHA bypass.
- Keep-specific source UI explains the unofficial integration and possible service/account restrictions. It provides date filtering, selection, export, and the existing preview/sync flow.
- Keep payloads keep stable string IDs, UTC timestamps, meters, seconds, original route/heart-rate samples when present. GCJ-02 coordinates are normalized once to WGS84. Missing GPS stays missing; indoor runs are genuine running FIT sessions with treadmill sub-sport, never silently marked uploaded or assigned invented coordinates.

## Sync architecture
The existing upload operation registry, OAuth token refresh, asynchronous poll, cancellation, stable fingerprint, durable final-FIT recovery, duplicate handling, and result history remain the single upload implementation. Running FIT carries sport metadata into Strava multipart requests. A successful HTTP acceptance is not completion: only final activity ID or positively identified duplicate completes the upload.

Activity metadata includes normalized sport and coordinate provenance. Running does not receive cycling commute titles, bicycle sensor supplements, cycling virtual power/weather requests, or cross-sport approximate duplicate matches. Unknown legacy sport remains conservative for cross-source approximate matches. Exact local identity/fingerprint dedup remains valid. Metadata survives batch checkpoints, recovery, saved history, and detail reopening; uploaded final bytes are never reprocessed on retry.

## Safety and limits
- No paid services, production credentials, health uploads, security relaxation, or Android Health Connect writing
- Fixed Keep endpoints, redirects blocked, bounded responses/decompression/page count and cancellation, redacted errors, no arbitrary remote file URLs
- Upload warning states selected route/heart-rate data goes to Strava and visibility follows Strava privacy settings
- Use existing Strava app configuration; app-capacity/access errors are actionable failures
- FRB bindings must be generated by the repository's audited offline adapter, with analytics disabled; never hand-edit wire bindings
- Protocol reference is MIT-licensed running_page, pinned to 6ffdd23ad8cd96118ba0cd93ccf07320676e01e3; retain attribution for derived logic
