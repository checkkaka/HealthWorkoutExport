# HealthWorkoutExport 详细使用教程

面向真机使用。凭证与同步状态只保存在本机；登录凭证仅直接提交给对应平台，不会上传到作者服务器。

快速入口：工程根目录 [README.md](../README.md)。

---

## 一、准备与安装

### 1. 打开工程

```bash
open HealthWorkoutExport.xcodeproj
```

### 2. 签名与运行

1. 在 Xcode 里选中工程 → **Signing & Capabilities** → 选你的 **Team**
2. 用 **真机** 运行（模拟器几乎读不到完整健康数据）
3. 首次进入「健康」页时，按系统提示允许读取体能训练、心率、路线等

### 3. 界面结构（三个页签）

| 页签 | 作用 |
|---|---|
| **健康** | Apple 健康训练列表、导出 JSON/FIT、合并 FIT、入口进自动同步 |
| **行者** | 账号密码登录后看行者活动 |
| **顽鹿** | 账号密码登录后看顽鹿活动 |

---

## 二、健康页：导出与合并 FIT（原功能不变）

### 导出训练

1. 打开 **健康** 页签，授权健康数据
2. 选时间范围：近 7 天 / 30 天 / 今年 / 自定义
3. 勾选要导出的训练（左上角菜单可全选）
4. 点右上角 **导出** → 选 JSON 或 FIT → 开始导出 → 用系统分享发出去

### 合并 FIT

1. 健康页左上角 **选择** → **合并 FIT 文件**
2. 可 **添加 FIT 文件**，也可 **从体能训练选择**
3. 选 1 条：直接导出 FIT；选 2 条及以上：点选 **主数据源**，其余按合并规则补缺
4. 设备时钟不一致时：用 **自动对齐** 或 **手动偏移**
5. 点 **合并 / 导出**，再分享结果文件

合并规则仍是：以主文件为准，副文件只补主文件缺失字段。

## 三、登录行者（账号密码，无需开发者 API）

对齐 WanSync / SyncOnelapToXoss 的网页会话方式。

1. 打开 **行者** 页签
2. 点 **登录行者**
3. 填行者账号、密码 → **登录行者**
4. 成功后用顶部时间范围筛选活动列表
5. 退出：左上角 `…` → **退出登录**

说明：

- 密码会 RSA 加密后走行者网页登录接口，拿到 `sessionid`
- 账号 / 密码 / `sessionid` 只存 Keychain
- Session 过期后重新登录即可

---

## 四、登录顽鹿（账号密码）

1. 打开 **顽鹿** 页签
2. 点 **登录顽鹿**，填账号密码
3. 成功后同样按时间范围看骑行记录
4. 退出：`…` → **退出登录**

顽鹿用签名登录 + 业务接口拉列表 / 下 FIT，凭证同样只在本机。

## 五、配置 Strava（同步目标）

入口：任意页签左上角 `…` / 健康页「选择」菜单 → **Strava 设置**。

支持两种模式，**默认 API**。

### 方式 A：API 模式（推荐）

1. 浏览器打开 [Strava API 设置](https://www.strava.com/settings/api) 创建应用
2. **Authorization Callback Domain** 填 `localhost`（或任意域；App 实际回调用自定义 scheme）
3. 记下 **Client ID**、**Client Secret**
4. App → Strava 设置 → 模式选 **API**
5. 填入 Client ID / Secret → **保存并授权 Strava**
6. 系统浏览器完成授权（需勾选上传活动相关权限）
7. 显示「已授权」即可

App 回调：`healthworkoutexport://localhost/callback`（授权回调域必须是 `localhost`）

### 方式 B：网页模式（API 上传受限时用）

1. Strava 设置 → 模式选 **网页**
2. **打开 Strava 登录** → WebView 里登录成功
3. 点 **完成**，App 保存 Cookie
4. Cookie 过期后按同样步骤重新登录

注意：网页模式**不能**在同一次上传请求里打「通勤」标签；通勤标记只在 API 模式生效。

**覆盖删除**不依赖把上传模式改成网页：日常可继续用 API；在 Strava 设置里额外完成一次「网页登录」保存 Cookie 即可。官方 API **没有**删除活动接口。

API 字段说明见 [Strava API Reference — Uploads](https://developers.strava.com/docs/reference/)。

## 六、自动同步（核心）

入口：健康 / 行者 / 顽鹿 任意页 → `…` 或健康「选择」→ **自动同步**。

### 步骤

1. **主数据源**：健康 / 行者 / 顽鹿 三选一（以谁为主时间轴与冲突裁决）
2. **补充数据源（可选）**：勾选非主源；未登录的源是灰的，需先去对应 Tab 登录
   - 可不勾：主源直接上传
   - 可勾一个或两个：同时间段匹配后，用现有 `FitMerger` 补缺再上传
3. **同步模式**
   - **同步当天**：本地日历「今天」内、以开始时间落在当天为准的活动
   - **同步历史**：近 7 / 30 / 90 天 / **全部** / 自定义起止
4. 确认 Strava 已配置（当前模式显示在页内）
5. 点 **开始同步**，看进度：上传 / 去重 / 失败

### 匹配与合并逻辑（自动）

对主源每条活动：

1. 在每个已勾选补源里找时间最吻合的一条（区间重叠优先；否则开始时间差 ≤ 15 分钟且时长差 ≤ 20%）
2. 某补源没有匹配 → 跳过该补源，不整条失败
3. 有补源 FIT → `FitMerger`（先自动对齐，失败再绝对时间）
4. 上传 Strava

### 幂等与两端区别

| 端 | 作用 | 清掉之后 |
|---|---|---|
| **本 App（本地）** | 指纹 + `sync_state.json`；实际上传成功的最终 FIT；勾选重传期间暂存受保护的 `pending_resync` 恢复文件 | `pending_resync` 上传成功自动清理；「同步记录」删单条/清空时一并删除最终 FIT；**不会**删 Strava 活动 |
| **Strava（远端）** | Uploads 黑盒判重（如 `duplicate of activity 123`）；API 模式还会按时间区间重叠预检 | 官方无删除 API；本 App「覆盖」用**网页 Cookie**删远端后再按当前模式重传 |

本地指纹：

`主源 + 活动 ID + 开始时间 + 勾选的补源集合 + strava`

- 已成功上传 → 再跑会 **去重跳过**
- 开「自动跳过已有同步记录」时：本地该主活动只要有过 uploaded 记录也会跳过（改补源不重传）；中断后点「继续上次同步」同理
- 改补源集合且关闭「跳过历史」→ 指纹变了，可能再传一次
- 预检命中或 Strava 返回 duplicate → 弹窗：**跳过** / **本批一律跳过** / **打开远端活动** / **覆盖** / **本批一律覆盖**
  - 「本批一律…」只对**当前这次同步**有效，下次开始同步会重新询问
  - 覆盖需先网页登录存 Cookie；删失败（如 Cookie 过期）会记失败，可重新登录后再继续

预检判据是**时间区间重叠比例 ≥ 50%**（交集/并集）。从哪个 Tab 进「自动同步」，主源就预填对应源；切换主源后补源会自动勾上其余已登录源。关闭自动同步页后同步仍可继续，顶部与同步记录页能看到进度。

### 同步记录

入口：自动同步页、或各 Tab 菜单 → **同步记录**。

- 只展示/删除本机幂等状态；同步进行中时页内有进度条，可取消
- 点有远端 ID 的记录 → 打开 Strava 该活动网页
- 点「选择」可勾单条、整批或当前筛选结果，再点「同步勾选」覆盖重传
- 勾选重传会在上传前保存最终 FIT；上传若失败，再次勾选会直接使用本地恢复文件
- 活动列表会为成功写入虚拟功率的记录显示「虚拟功率」，本机仍保存上传文件时显示「同步 FIT」
- 导出 FIT 时可选「原始文件」或「Strava 同步版」；所选记录任一缺少同步 FIT 时后者置灰，旧记录需重新同步一次后才可用
- 滑动删除单条；工具栏可清空全部
- 清空后不会动 Strava 上的活动

列表里带绿色印章的活动表示本地已有同步记录；点活动可看基本信息。

### 通勤自动标记（仅 API 模式）

满足任一条件则上传时 `commute=1`：

- 距离 **&lt; 5 km**
- 或平均速度 **&lt; 28 km/h** 且距离 **&lt; 16 km**

## 七、推荐日常流程

### 骑完当天同步

1. 行者、顽鹿（若要用）先登录
2. Strava API 已授权；若可能要「覆盖」，再在设置里做一次网页登录存 Cookie
3. 自动同步 → 主源选你最信任的（常见：顽鹿或健康）
4. 按需勾补源 → **同步当天** → 开始同步
5. 再点一次应大量「去重」，确认幂等正常

### 补传历史

1. 自动同步 → **同步历史**
2. 选 7 / 30 / 90 / **全部** 或自定义日期
3. 开始同步（「全部」可能较久，保持 App 在前台）

### 只合并不上传

仍用健康页的 **合并 FIT**，与自动同步无关。

## 八、常见问题

| 现象 | 处理 |
|---|---|
| 健康页没数据 | 真机 + 重新授权；确认该时段 Apple 健康里确有训练 |
| 行者登录失败 | 核对账号密码；网络/风控时稍后重试；退出后重登 |
| 顽鹿登录失败 | 核对账号密码；顽鹿侧风控时改天再试 |
| Strava API 授权失败 | Client ID/Secret 是否配对；回调 domain；scope 是否含上传与读活动；改 scope 后需重新授权 |
| 网页模式上传失败 | Cookie 过期，重新 WebView 登录 |
| 覆盖失败 | 删除失败时重新网页登录；远端已删但上传失败时，回到同步记录再次勾选即可使用本地恢复文件重试 |
| 轨迹在 Strava 偏移 | Strava 设置打开「上传前 GCJ-02 → WGS-84」（默认关；HealthKit 一般不用） |
| 想重传同一条 | 同步记录里删本地记录；若远端仍在，选覆盖或先手动删 Strava |
| 未打通勤 | 确认是 API 模式，且距离/均速满足规则 |

## 九、安全提醒

- 行者 / 顽鹿 / Strava 凭证只在本机 Keychain
- 不要把账号密码、Client Secret、Cookie 发给别人或提交到 Git
- 本工具与 Apple、行者、顽鹿、Strava 官方无隶属关系，使用后果自负
- 网页 Cookie 删除活动为非官方能力，可能随 Strava 网页改版失效
